# 文件创建与删除验证

日期：2026-11-17。Node 22.22.0，Windows，Chrome 真实页面。

## 实现

- 使用项目 frontend-design、shadcn skill，沿用现有灰白配色、Geist 字体、目录位置布局和 Base UI 组件。
- 工具栏在当前任务根目录创建空文件；文件夹的行内菜单与右键菜单支持在该目录内新建文件。名称保留原样，可包含中文、空格、扩展名，也支持无扩展名文件。
- 普通文件的行内菜单与右键菜单共享删除逻辑；链接和特殊文件不显示文件删除入口。
- 文件与文件夹共用创建对话框、名称与路径验证、服务端绑定检查、每个 chat 的写入队列、分支刷新和短暂 Toast。没有常驻成功消息或 Selected 卡片。
- 删除显示名称、完整任务相对路径、永久删除且不进入回收站的说明；默认焦点取消。服务端要求显式确认，复查文件身份、大小与修改时间等元数据，文件变化后需要重新确认。
- 保持 master，未提交；没有数据库结构、依赖、模型调用或根目录迁移改动。

## 浏览器验证

仅创建并操作专用目录 `__file_ui_review_20261117/`、其中的 `研究 笔记.md` 和根目录文件 `__file_ui_root_20261117.md`，测试后已清理。原有 data、docs、outputs、src、test 均保留。

- 文件夹菜单打开不会展开目录；新建成功后该目录自动展开，文件出现在对应父目录并高亮。
- 已选中目录内文件时，顶部新建仍展示“当前任务根目录”，落盘位置确为根目录。
- 中文与空格文件名可创建，文件为空；`bad/name.md` 被拒绝；同名创建显示冲突并保留输入；Esc 可取消。
- 文件右键菜单与行内菜单均可打开删除确认；普通文件只提供文件删除。
- 删除确认默认按 Enter 会取消；磁盘文件仍存在。
- 对话框打开后修改本轮测试文件，再点击删除，返回“文件已变化，请核对后重新确认删除。”；文件仍存在。再次明确确认后删除成功。
- 文件删除后，父目录重新读取并显示为空；其他分支保留。
- 文件已被另一操作删除时，提交删除会关闭对话框并同步移除树中旧节点。该场景的 3 秒 Toast 未抓拍到，不以截图声称验证了具体提示文案。

## 限制与未验证项

- 未实测触摸设备、真实中文输入法组合输入、请求已提交但未完成时切换聊天、活跃流式输出期间操作、大于 200 项目录的浏览器展示；相关行为复用既有防护和树更新逻辑，不列为本轮浏览器实测通过。
- 路径验证与确认信息不构成操作系统级文件锁；无法承诺抵御恶意本机进程在检查与系统调用间持续替换目录的全部 TOCTOU 竞争。
- 使用 Node 文件系统 API，不调用 shell 删除。参考 [Node 22 fs 文档](https://nodejs.org/docs/latest-v22.x/api/fs.html#file-system-flags)：独占创建使用 wx，文件删除使用 unlink。删除不提供回收站或撤销。
